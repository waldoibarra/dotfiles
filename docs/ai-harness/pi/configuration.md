# Pi configuration

**Ownership:** Tracked preferences live under [`home/.pi/agent`](../../../home/.pi/agent).
The settings sync merges defaults into a local file; Dotbot links the other managed files.
The profile directory stays real; credentials and runtime data stay outside the repository.

## Coding defaults and packages

The coding defaults are `defaultProvider: "openai-codex"` and `defaultModel: "gpt-6-astra"`.
Automatic compaction is enabled through `compaction.enabled: true`.
Packages declare voice and `git:github.com/waldoibarra/pi-lens@latest`.
The Lens declaration disables package skills and prompts with empty filters.
Use [editing settings](#edit-persistent-settings) for persistent preferences and package
declarations.
Pi UI changes remain local; sync restores values managed by tracked defaults.
Keep secrets and machine-specific values outside tracked files.

Read [Lens compatibility](/docs/ai-harness/integrations.md#pi-lens) before relying on Lens after
upgrading Pi.

Authentication, sessions, caches, native binaries, and voice locks stay outside Git.
This configuration step does not link, copy, or remove them.
Read [installation and sync](installation.md) before reconciling packages.

## Edit persistent settings

**Edit `home/.pi/agent/settings.json`, then deliver it with the targeted sync command.**
Do not edit the installed copy for portable changes or copy its runtime fields into Git.

1. Read this guide and the installed Pi settings reference for the requested setting.
2. Edit the tracked source, preserving unrelated defaults.
3. Run `python3 scripts/update-coding-agents/sync-pi-settings.py` from the repository root.
4. Wait for the current response to finish, then run `/reload` or start a fresh Pi session.
5. Inspect the requested setting in the installed file and verify its relevant Pi behavior.

The command changes only normal-profile settings; it does not update packages, authenticate, or
run a model.
It ignores inherited `PI_CODING_AGENT_DIR` trial profiles.
Package changes also need [reconciliation](installation.md#provisioning-sequence).
`models.json` and `keybindings.json` remain linked; editing their tracked sources needs no
settings sync.

### Merge ownership

Every top-level key present in tracked settings owns its entire installed value.
Objects and arrays are replaced, not recursively combined.
For example, removing a nested compaction override or package entry removes it on the next sync.
Unspecified top-level keys remain local, including `lastChangelogVersion` and extension changelog
markers.

Removing an entire tracked key relinquishes ownership; it does not delete the installed value.
To restore an upstream default, remove that specific key from both files within the approved change.
Never replace the whole installed file with tracked defaults; that would discard local state.
UI changes to managed keys last until the next sync.
Promote intended portable preferences by editing their tracked counterparts.

### Migration, verification, and recovery

Dotbot installation and the coding-agent updater invoke the same
[settings sync](/scripts/update-coding-agents/sync-pi-settings.py).
It atomically replaces the old tracked-source symlink with a regular file, preserving existing
local values.
The source remains unchanged.
New files use mode `0600`; existing regular files retain their permissions.
Semantically matching regular files retain their bytes and timestamps.

Malformed JSON, unrelated symlinks, and active settings locks stop delivery without replacing
settings.
Retry after the writer finishes.
For an abandoned `settings.json.lock`, verify no writer remains before removing that lock directory.
Avoid changing settings concurrently during migration or delivery.

Run isolated regression checks without touching the workstation:

```sh
python3 scripts/tests/test-pi-settings.py
```

After delivery, confirm `~/.pi/agent/settings.json` is not a symlink.
Check the requested values and preserved local state without printing unrelated private settings.
Run the targeted sync again; unchanged settings should report `Pi settings already current.`
These checks establish delivery, not fresh-session model compliance.

To undo a preference change, revert its tracked value and rerun the targeted sync.
To reverse this delivery architecture, first save the installed settings outside Git.
Restore the previous installer and updater together before restoring the symlink.
That rollback reintroduces runtime writes into Git.

## Laptop image rendering

`terminal.images: "kitty"` selects the native Kitty image protocol for Ghostty through Herdr.
Ghostty starts Herdr through [its tracked configuration](/home/.config/ghostty/config).

The override was introduced after Pi 1.1.0 disabled automatic image detection for
`TERM_PROGRAM=herdr`.
That check used Ghostty 1.3.1 and Herdr 0.9.3.
[Herdr 0.9.3 supports Kitty graphics][herdr-kitty], including local Ghostty clients.
The override avoids changing terminal identity; it does not establish compatibility with every
terminal.

[herdr-kitty]: https://github.com/herdrdev/herdr/blob/v0.9.3/docs/next/website/src/content/docs/configuration.mdx#kitty-graphics

Wait for the response to finish before reloading changed settings.
Run `/reload`, then expand an image-bearing result.
The setting changes rendering only; it does not change image uploads or model input.
Lens keeps tool results collapsed until opened.
Pasted-image tokens require compatible host metadata; installing Lens does not add that host
support.

This preference applies to every terminal using the normal profile, not only this laptop.
Moshi and other terminal stacks remain unverified.
Use `"auto"` or remove `terminal.images` to restore detection.
Use `false` to disable inline image protocols.
Deliver settings using [editing settings](#edit-persistent-settings); no full `dots` or package
installation is required.

## Queued messages

`steeringMode: "all"` delivers pending steering messages together at the next native tool-batch
boundary.
Enter uses steering while Pi works; Alt+Enter requests a follow-up after the current work.
This does not interrupt an active model response or an unfinished tool batch.
A Codemode call remains one outer tool call, even when it contains several operations.

Deliver the preference using [editing settings](#edit-persistent-settings), then run `/reload`
after the response finishes.
This setting does not provide an immediate background handoff.
Read [Claude's queue behavior](https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued)
before comparing messages with queued slash or shell commands.

## Extended context and compaction

`models.json` sets `providers.openai-codex.modelOverrides[MODEL_ID].contextWindow` to **1,050,000**
for each of these exact model IDs. In `settings.json`, the corresponding
`compaction.modelOverrides["openai-codex/MODEL_ID"].reserveTokens` is **128,000**.

| Model ID | Total context | Response reserve |
| --- | --- | --- |
| `gpt-5.5` | 1,050,000 | 128,000 |
| `gpt-5.6-luna` | 1,050,000 | 128,000 |
| `gpt-5.6-sol` | 1,050,000 | 128,000 |
| `gpt-5.6-terra` | 1,050,000 | 128,000 |
| `gpt-6-astra` | 1,050,000 | 128,000 |
| `gpt-6-luna` | 1,050,000 | 128,000 |
| `gpt-6-sol` | 1,050,000 | 128,000 |
| `gpt-6.1-sol` | 1,050,000 | 128,000 |

`gpt-5.3-codex-spark` retains its catalog window of **128,000**, without an override. The expanded
models leave 922,000 tokens before the response reserve. The reserve also affects compaction
summary limits; it is not only a trigger threshold.

A previous loading check displayed Astra as `1.1M (auto)`, rounding the total window.
Requests beyond the previous 272,000-token catalog limit were not tested against the subscription
backend. Client metadata and published model capacities do not prove backend acceptance at the
maximum window.

The integration retains the tested overrides.
Recheck native Pi support and model specifications before changing them.
New model IDs do not inherit these values automatically.

## Keybindings

The local `keybindings.json` contains:

```json
{
  "app.model.select": [],
  "app.tree.filter.labeledOnly": "alt+l"
}
```

These overrides avoid conflicts with the voice extension's Ctrl+L shortcut.
`/model` opens the model selector; Option+L selects the tree's labeled-only filter.
After editing, run `/reload` and inspect `/hotkeys` for effective bindings.
[Live voice](live-voice.md) lists voice controls and commands.

## Instructions and skills

Pi natively discovers `~/.agents/skills`; there is no second skill copy or new Skills CLI target.
Its global `AGENTS.md` supplies shared policy and directs sessions to the vault and machine-local
profile links.
Read [personal profile routing](/docs/ai-harness/instructions.md#personal-profile-routing) before
provisioning those links or removing an obsolete `~/AGENTS.md` selector.
Coding context does not replace the extension's separate hardcoded voice prompt.

`AGENTS.override.md` is an upstream Pi convention, not a file created by these dotfiles. If present,
it takes precedence over an ordinary context file in the same directory. A profile override can
therefore replace the linked global instructions; a project override affects that directory's
context. This integration neither creates nor requires an override file.

### Third-party skill compatibility

**Keep third-party skills unchanged.**
Some request Claude Code's `Skill` tool, which this Pi setup lacks.
Pi loads skill instructions through `read` instead.
[APPEND_SYSTEM.md](/home/.pi/agent/APPEND_SYSTEM.md) owns this compatibility instruction;
shared `AGENTS.md` remains client-neutral.
Dotbot installs its link through [install.conf.yaml](/install.conf.yaml).

Pi appends this file to its system prompt without replacing shared instructions or its default
prompt.
A trusted project's `.pi/APPEND_SYSTEM.md` replaces the global append file; Pi does not combine
them.
Projects using that override must explicitly retain any needed compatibility instruction.
The [upstream configuration guide](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/configuration.md)
documents this precedence.

After installing the link, start a fresh session or run `/reload`.
Verify isolated delivery and native prompt loading without inference:

```sh
PI_PACKAGE_DIR=/path/to/pi-package node scripts/tests/check-pi-skill-compatibility.mjs
```

The check covers repeated linking, shared-policy preservation, and trusted project override
precedence.
It does not prove model compliance; exercise `/skill:grill-with-docs` separately in a fresh session.

Read [Agent coordination](../agent-coordination/spawning.md) before starting Pi workers.
Read [personal MCP setup](../mcp.md) before changing servers or testing shared client access.
