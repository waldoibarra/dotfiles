# Proposal

## Why

Mandatory design documents duplicate reasoning already captured during task refinement.
Prototype requests need a throwaway learning route rather than a durable specification workflow.

## What Changes

- Add a native three-artifact schema, with specifications skipped only for behavior-preserving changes.
- Keep prototypes outside OpenSpec and require separate approval before production promotion.
- Link the session guide and schema through a stable installed reference.
- Deliver the shared schema through Dotbot and select it only for new dotfiles changes.
- Preserve Pi, Claude Code, and Cursor access through their existing shared skills.
- Test native resolution, skipping, validation, task tracking, and archiving in disposable projects.

## Capabilities

### New Capabilities

- `session-workflow`: Low-ceremony durable changes and separate throwaway prototype routing.

### Modified Capabilities

None. The existing harness-adoption change remains active under its original schema.

## Impact

Changes affect shared instructions, the session guide, native OpenSpec configuration, schema templates,
and isolated delivery checks.
Existing skills remain canonical procedure owners; the external prototype skill stays unchanged.
No company repository, historical artifact, or broad documentation layout is migrated.
