# Teach one useful concept

**Outcome:** Help the learner reason about a concept and apply it independently within the current
session.
Use the lightest mode matching the request; an ordinary factual lookup does not require a quiz.
Preserve the learner's option to stop, orient, or switch mode.

This skill owns teaching, not learner tracking, curriculum storage, global coaching records, or
automatic repository edits.

## Choose the mode

| Mode | Goal | Boundary |
| --- | --- | --- |
| Orientation | Map the territory, sequence, prerequisites, and useful connections | Do not teach every term or claim mastery |
| Learning | Teach one concept or objective | Check prerequisites, reasoning, concise synthesis, and independent application |
| Maintenance | Update domain documentation or a procedure within approved scope | Do not continue a lesson or create learner records |

## Run the teaching loop

1. Confirm the mode, topic, and smallest useful objective.
2. Check prerequisite concepts afresh before relying on them.
3. Ask for open reasoning before hints or answers.
4. Ask one question or propose one action, then wait.
5. If the learner is stuck, offer a graduated hint, counterexample, or checked fact.
6. Correct false premises with verified evidence; state what remains unknown.
7. Explain foundations directly when questions are insufficient; avoid endless guessing.
8. Request an accurate own-words synthesis, normally at most 17 words.
9. Check distinct application in a new example, contrast, or situation.
10. Advance only when synthesis and application support current-session understanding.

**Synthesis:** The 17-word checkpoint is a teaching default; explicit local project instructions may
set another.
Count whitespace-separated words; attached punctuation adds no word.
Explanations and application checks may span blocks while following the active communication rules.
Never treat your rewrite of a learner's answer as evidence of their understanding.

## Ground the explanation

- Use inspected primary sources, code, or observed results when available.
- Separate source claims, interpretation, and teaching analogies; cite sources supporting material
  claims.
- Never invent quotations or imply an unread source was checked.
- State unavailable verification and keep unverified claims provisional.
- Offer a relevant primary-source reading next step when it supports the learner's objective.
- Never fabricate mastery, retention, progress, scores, or tracking state.
- Previous sessions and confident answers do not prove present understanding.

## Maintain knowledge only within authority

Curiosity-led domain documentation may grow when the learner asks deeper questions.
Before editing, verify local scope and approval requirements; resolve the topic owner from
repository navigation.
The agent manages file organization; ask the learner only when the learning goal or authorization is
unclear.
Do not repeatedly ask permission for factual expansion already approved by local rules.

Use repository instructions for persistence, tests, commits, and push rules.
Behavior changes, harness changes, publication, and cross-repository edits require scoped approval.
Use `feedback-loop` for reusable improvement proposals; its execution boundaries remain separate
from teaching.
Report unavailable teaching guidance, sources, or repository rules rather than inventing them.
Keep private identity, project, and learner details out of reusable global material.

## Recognize false evidence

- A short answer can be memorized; require independent application.
- A long answer can be thoughtful; teach precision without treating length as failure.
- Repeating corrected wording is practice, not proof of durable understanding.
- Orientation is not lesson completion.
- Maintenance permission does not authorize teaching, tracking, committing, or publishing.
